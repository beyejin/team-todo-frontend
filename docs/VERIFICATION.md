검증일: 2026-10-26. 별도 Next.js 프론트엔드의 로컬 실행 결과입니다. 외부 배포 결과가 아닙니다.

## 자동 검사

`npm run check`에서 ESLint(경고 0), Prettier, strict TypeScript, Vitest **148개**, production build가 모두 통과했습니다. 건너뛴 프론트 테스트는 없습니다. 모든 명세 경로가 빌드됐습니다.

- API: 7개 동작, Task/TaskPage 런타임 검증, 400/401/404/422/500·비JSON·네트워크 오류, Abort 전달.
- 필터: 복수 상태, 기본값·URL 복원, 날짜 범위·잘못된 날짜, 변경하지 않은 날짜의 초·밀리초 보존.
- 폼: 제목 검증·전 필드 생성·PATCH 변경분·null/빈 배열 처리·응답 유실 안내·입력 보존·중복 제출 차단.
- 화면: 로딩/조회 실패/404 재시도, 최신 응답 유지, 삭제 취소·실패·중복 차단, 복구 후 마지막 페이지 보정.
- 탐색/테마: 링크·새로고침·뒤로/앞으로 보호, Next history 상태 보존, 쿠키 테마 복원·저장 제한 대응.

커밋 게이트는 실제 임시 Git/Husky에서 부분 스테이징 오류, 포맷 오류, 테스트 파일 삭제만 포함된 커밋을 차단하고 index·작업 내용을 보존하는 것까지 확인했습니다. 자세한 절차는 [HARNESS.md](HARNESS.md)에 기록했습니다.

## 과제 #8 칸반 추가 검증

2026-10-26 최종 전체 검사에서 프론트 **148개**(기존 95 + 칸반 클라이언트·화면 48 + 서버 프록시 5)가 통과했습니다. ESLint·Prettier·strict TypeScript·production build도 통과했습니다. 백엔드 작업 트리의 전체 검사는 **백엔드 46개·CLI 51개**가 통과했으며, 격리 PostgreSQL 변수를 설정해 건너뛴 DB 검사가 없습니다.

- 칸반: UUID·필드 검증, 100개 이후 전체 페이지, 조회 중 목록 변경·중복 카드 감지, 등록·버튼·드래그 이벤트, 중복 요청 차단, 실패 시 입력·원위치 보존.
- 프록시: 토큰 서버 한정 사용, 허용 경로, 교차 사이트 쓰기 거부, no-store, 내부 오류 비노출. 서버 응답 유실이 JSON 502가 되는 경우도 재등록 전에 저장 여부 확인을 안내합니다.
- 백엔드: 같은 상태 요청의 불변성, 보드·멤버 범위, 목표 컬럼 누락, 트랜잭션 롤백, 동시 생성·이동 순서, 제한 역할의 최소 UPDATE 권한.

### 실제 Supabase — 연결 전 확인

Supabase 대시보드의 읽기 전용 조회로 `kanban-team6` 프로젝트, 기존 `Assignment #3 Board`, 세 상태 컬럼, 기존 업무 4개, workspace 멤버와 `ttodo_worker` 역할을 확인했습니다. 현재 역할에는 상태 이동용 UPDATE 권한이 없습니다.

로컬 백엔드의 DB 접속 정보가 없으므로 **프론트 → 실제 Supabase 등록·조회·상태 이동은 아직 미완료**입니다. 원격 권한 SQL도 승인·실행 전입니다. `002_worker_status_update.sql`의 검증 통과는 격리 DB에 대한 결과입니다. 공유 업무를 등록했다고 보고하지 않습니다.

사용자 수동 테스트 전체와 별도 브라우저 간 실제 원격 공유, 실제 드래그, VoiceOver 낭독은 남은 확인 항목입니다. 발표 전에 실제 접속 정보·최소 수정 권한을 설정하고 FE-KB-001부터 순서대로 진행합니다.

## 확인 범위와 남은 사용자 수동 확인

- 수동 테스트 문서 전체를 통과 처리하지 않습니다. 위에 적힌 실제 실행 흐름과 단위·컴포넌트 검증을 구분합니다.
- VoiceOver 낭독, 모든 브라우저 조합, 브라우저 완전 종료 후 재방문, 두 테마×두 해상도 전체 CRUD 조합은 사용자 수동 확인 항목으로 남깁니다.
- 현재 Chrome에서 모든 요소에 `style="user-select:auto"`가 추가되어 React hydration 경고가 발생했습니다. 서버 HTML에는 해당 스타일이 없고, 확인한 경고 diff는 이 삽입 스타일 차이였습니다. 브라우저 확장 기능의 개입으로 추정하며 앱 코드에 경고 억제를 추가하지 않았습니다. 확장 기능 없는 브라우저의 초기 렌더링은 별도 확인이 필요합니다.
- Playwright E2E 스위트는 추가하지 않았습니다. 실제 UI 확인은 브라우저를 직접 조작해 수행했습니다.
